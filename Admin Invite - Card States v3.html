What changed from v2

  • change shortcut next to the recipient email

Why a dialog instead of an inline change-shortcut.
  • Editing the address and sending the email are the same intent. A separate change link splits one action into two clicks.
  • The dialog is a single commit point. There's no ambiguity about whether typing changed anything — the user either clicks Send (the address is saved + emailed) or Cancel (nothing changes).
  • For link-only state (01b), the same dialog opens with an empty field, so the "first send" path is identical to "re-send to same address" path.
  • If you only ever want to update the recipient without sending, that's a Regenerate (since it'd be weird to keep an old token bound to a new address). One less concept to teach.
