CARBON ADMIN · DESIGN SPEC · 2026-05-27
Devices · 搜索规则设计方案
面向"大批量设备列表"的搜索体验。要求：搜索由按钮显式触发，并提供 高级搜索条件。本方案不修改既有代码，仅输出规则、字段映射与三套视觉/交互方案。
Scope · /devices
Owner · Admin Portal
Status · For review
01

现状与目标

为什么要改

现状：实时输入即过滤

  • 仅 1 个关键字框 + 2 个下拉（Model / Status）
  • 每次按键都重新过滤，设备数过万时前端卡顿
  • 无法筛选 IMEI / MAC / SSID / Carrier / 最后心跳 / 磁盘 / 电量 等字段
  • 没有"保存搜索"，每次进页面都要重新选条件
  • URL 不带过滤参数，分享/刷新会丢失上下文

目标：显式触发 + 高级条件

  • 关键字框 + 显式 Search 按钮，回车也可触发
  • 所有条件 编辑期暂存，点击 Search 才向后端请求
  • 覆盖 20+ 设备字段，按 5 个域分组（识别 / 归属 / 状态 / 网络 / 安全）
  • 条件可保存为"我的视图"，URL 完整携带，可分享、收藏、刷新
  • 结果区显示活跃过滤条件 chip，可单条移除
02

搜索行为规则

何时触发、如何触发、结果如何展现
R-01 · TRIGGER
仅由显式动作触发请求
① 点击 Search 按钮；② 在关键字框按 Enter； ③ 高级面板内任意条件回车。
禁止 onChange 实时查询——大设备量下会反复打表/拖垮服务。
R-02 · KEYWORD
关键字框 = 仅按 sn 搜索
只匹配设备序列号（完整或前缀），不再做"全字段模糊"——SN 是设备的唯一锚点，模糊跨字段反而拖慢索引、增加误命中。
支持 多值粘贴：以空格、逗号或换行分隔，自动转为 OR 列表（一次最多 200 条），覆盖批量查 SN 场景。
IMEI / MAC / SSID / 商户 等查询走"高级搜索"。
R-03 · ADVANCED
高级条件 = 编辑期暂存
打开高级面板修改条件时，结果区不动；
底部固定 Search + Reset， 只有 Search 才会触发查询；Reset 仅清空高级条件、保留关键字。
R-04 · ACTIVE CHIPS
活跃条件以 chip 形式持续可见
搜索成功后，工具栏第二行展示已生效的过滤条件，例如 Model: N950, S60 × Last seen ≤ 24h ×。 点击 × 单独移除即重新查询。
R-05 · URL & SHARE
条件写入 URL Query
每次成功搜索后写 URL，例： /devices?q=N950&state=active&lastSeen=24h&model=N950,S60
支持刷新还原、分享 / 工单中粘贴定位。
R-06 · SAVED VIEWS
支持"我的视图"
常用条件可命名保存（如"待激活 - 本月"、"低电量"），出现在关键字框左侧的视图切换器； 可设为团队公共。最近 5 条搜索自动进入"最近"。
R-07 · PAGINATION
服务端分页 + 计数
搜索结果支持服务端分页（50 / 100 / 200/页），总数与翻页器固定在表底； "Export" 走异步任务，不在前端组装。
R-08 · A11Y & PERF
键盘 + 加载态
/ 聚焦关键字框，⌘F 打开高级面板， Esc 关闭；请求期间结果区半透明 + spinner，按钮 disabled。

i
分组原则
5 大类是用户心智路径："找一台 SN" → 识别；"商户的所有终端" → 归属； "近 24 h 离线" → 状态；"用电信卡的" → 网络；"被 root 的" → 安全。 单组之内 AND，组与组之间 AND。需要 OR / 嵌套时走方案 B（条件构建器）。

2

门店选择器 · 级联规则：
• 未选商户 → 禁用 + 占位 "先选商户"；
• 已选商户 → 异步加载该商户下门店列表，下拉显示 "门店名 · 设备数"，支持模糊搜索；
• 多选时勾完点 Apply 收起；超过 3 个折叠为 "+N more"。
4
主 Search 按钮始终可见，Enter 等价。 注：选商户或门店不会自动查询——与 R-01 一致，所有条件都必须点 Search 才发起请求；商户级联只影响门店候选列表。
5
Advanced 按钮 → 打开右侧 Sheet（见下方）； 按钮角标显示已配置的高级条件数（图中 "3"），即使 Sheet 关闭也能感知。

09

列表设计 · 字段过多时如何展示

22+ 字段不可能一行塞下 — 5 个组合策略
L-01 · DEFAULT COLUMNS
默认 7 列 = 最高频识别字段
SN / Model / OS·Firmware / Merchant / Last seen / Posture / Status。 其余字段（IMEI / MAC / Storage / Battery / Network / Apps…）默认隐藏， 通过"列管理器"开启。
L-02 · STICKY COLUMNS
固定首列 SN + 末列 Status
横向滚动时 SN 永远可见（识别锚点）；Status + 行操作图标固定右侧。 中间列横向滚动，⇧ + 滚轮平移。
L-03 · COLUMN MANAGER
列可显隐 / 拖拽排序 / 调宽
顶部 ⚙ Columns 打开抽屉式列管理器，按字段域分组勾选； 列宽拖拽吸附 80 / 120 / 160 / 200 px；配置随保存视图一并存。
L-04 · DENSITY
行高三档
Compact 32 px / Standard 44 px（默认）/ Comfortable 56 px。 Compact 模式下电池/磁盘用迷你进度条而非数字+条形。
L-05 · EXPAND ROW
行内展开看二级信息
每行最左 ▸ 图标展开 → 4 列网格显示 IMEI / MAC / 电量 / 磁盘 / Network / Apps 概要。 适合"不切到详情页就想瞄一眼"。
L-06 · PREVIEW DRAWER
点击行 → 右侧预览抽屉
替代直接跳转详情页：右抽屉显示完整摘要 + "Open detail" 按钮。 列表上下文不丢失，可连续浏览多台设备。

9.7

反模式 · 不要这么做

× 不要：22 列全塞一行

  • 水平滚动条比表格还宽，找列靠"扫描"
  • 缩小字号塞下去 → 11 px 数字，谁都看不清
  • 列宽都拉到 60 px → 序列号被裁成 "N950-..."

✓ 要：默认 7 列 + 4 套预设 + 列管理器

  • 列宽永远 ≥ minWidth，文字不裁不挤
  • 切场景靠预设而非每次重勾
  • 真要看全部 22 字段 → 点行 → Preview Drawer

× 不要：让用户自由拖列且每次刷新都重置

  • 拖完一遍 F5 全没了，心智负担
  • 无法分享"我看到的这一版列"给同事

✓ 要：列配置存进"我的视图"+ URL

  • 命名保存、设为默认、分享 URL 即同步列序
  • 团队视图 = 组内强一致；个人视图 = 自由发挥

× 不要：把详情字段塞进每一行

  • 电量条 + 磁盘条 + IP + IMEI 一行 7 个视觉元素 → 列表变仪表盘
  • 密度差，眼睛找不到序列号

✓ 要：分层信息架构

  • 列表层：1 个标识 + 3–5 个分类信息 + 1 个状态
  • 展开层：行展开看二级 / 抽屉看完整
  • 详情页：操作 + 日志 + 完整字段
i
列管理 · 推荐落地组合
① 4–5 个场景预设（Overview / Network / Security / Hardware / Apps）一键切换； ② Columns 抽屉在预设之外提供完整 22 列的显隐 / 排序 / 固定 / 宽度； ③ 固定 SN（左）+ Status（右）无论怎么切，识别锚点永远可见； ④ 行内展开 + 预览抽屉承接"不进详情页就想多看几个字段"的需求； ⑤ 响应式优先级窗口变窄按 priority 自动收，<768 px 直接卡片化。 这五件套配合就能既保持默认页面清爽，又能在任何场景下把对的字段呈现到位。

分页规则 · Pagination

服务端分页 + 大数据量优化
P-01 · SERVER-SIDE
必须服务端分页
12,000+ 设备前端无法 hold 住，必须 ?page=N&size=N 走后端。 首屏只请求第 1 页 + 总数。
P-02 · PAGE SIZE
默认 50 / 可选 25 / 50 / 100 / 200
50 是密度与一次性扫读量的平衡。允许的最大值取决于网络与导出策略； 500 以上必须走"导出 CSV"而非直接渲染。
P-03 · NUMBERED PAGER
数字翻页器 + 跳页
← 1 2 … 247 248 249 250 251 … 498 → · 中间窗口 ±2； 末尾 + 跳页输入框 Go to。
P-04 · STATUS LINE
展示当前范围 + 总数
Showing 12,401–12,408 of 12,408， 高级搜索结果加 filtered from 38,210 total。
P-05 · CURSOR FALLBACK
≥ 10 万行用游标分页
不再显示总数，改 Load more 或 ← Prev / Next →； 按 created_at < cursor 翻页，避免 deep offset。
P-06 · URL SYNC
page / size 持久化
翻页后 URL 同步：?page=249&size=50， 配合搜索参数支持刷新还原 / 分享。改 size 时回到 page=1。
P-07 · CROSS-PAGE SELECT
跨页全选 = 显式确认
表头勾选 = 选当前 50 行；上方出现横幅 "已选当前 50 行 · 选择全部 12,408 行 →"， 用户点确认才升级为全集。
P-08 · LOADING & EMPTY
骨架屏 + 翻页保留旧数据
翻页时旧数据保留但变灰 + 顶部进度条，避免高度跳动； 错误态显示 Retry，超过页码上限自动回到末页并提示。

页码与搜索的关系
① 任何"搜索 / 改条件 / 改 Sort / 改 Page Size"都重置 page=1； ② 翻页只改 page，其它过滤参数保持； ③ 删除/操作设备后留在当前页，不要因为列表少一行就自动翻页； ④ 排序与翻页都由后端响应，前端只是参数传递者。

推荐落地路径

Phase 1 · 核心搜索 + 列表骨架（2–3 周）

  • 替换现有 onChange 过滤 → 显式 Search 按钮 + Enter 触发
  • 关键字框支持多值粘贴
  • 方案 A 高级面板（5 大分组，14 个最常用字段）
  • 结果上方 chip 行 + 单条移除
  • 默认 7 列 + 固定首/末列（L-01 / L-02）
  • 服务端分页 + 数字翻页器 + 状态行（P-01 / P-03 / P-04）
  • URL Query 写入与还原（q / state / page / size）

Phase 2 · 列管理 + 进阶（4–5 周）

  • 列管理器（显隐 / 排序 / 固定 / 宽度）
  • 展开行 + 预览抽屉，密度三档切换
  • 跨页全选 confirm banner + 批量操作（push / disable / export）
  • 我的视图 / 团队视图，含列配置一并保存
  • 方案 B 条件构建器，Simple / Builder 切换
  • 异步 CSV 导出走任务中心；超过 500 行禁止前端渲染
  • 窄屏自动降级为方案 C 抽屉
  • / 聚焦、⌘F 展开、J/K 翻台等键盘加速
✓
最小可用版本（MVP）
如果只能改一处：保留现有 Input + 两个 select，在 Input 右侧加一个主色 Search 按钮， 并把 onChange 过滤改成"Enter / 点击 Search 才查询"。这一步成本最低、收益最大—— 其余按 Phase 1 / 2 推进。
